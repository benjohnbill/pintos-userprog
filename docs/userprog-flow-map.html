2예측Cargs-single

유저가 스택에서 인자를 꺼낼 수 있나

커널이 문서 방식(문자열은 마지막 인자부터 위쪽 · 8바이트 정렬 · argv[argc] = NULL · 가짜 반환 주소)으로 args-single onearg의 스택을 쌓았다. USER_STACK = 0x47480000. 유저 main은 argv 하나만 들고 "onearg"까지 직접 따라가야 한다. 따라가는 길의 칸(주소 → 담긴 값)을 순서대로 적어라. 커널이 argv[1]에 스택 안 사본 대신 커널 쪽 명령줄 버퍼 주소를 넣었다면?

단서

args-*는 유저 main이 이 길을 따라 찍은 줄을 .ck와 글자 그대로 비교하므로, 한 칸만 틀려도 출력이 어긋나거나 폴트로 죽는다.

문서 표에서 /bin/ls의 시작 0x4747ffed 다음 칸이 왜 0x4747ffe8인지부터. "onearg\0" = 7바이트, "args-single\0" = 12바이트. 문자열 영역 끝 주소가 문서 예시와 우연히 같아지는지 확인

답
0x4747fff9  "onearg\0"         argv[1] 문자열   (0x47480000 - 7)
0x4747ffed  "args-single\0"    argv[0] 문자열   (- 12)
0x4747ffe8  패딩 5바이트       8의 배수로 내림
0x4747ffe0  0                  argv[2] = NULL
0x4747ffd8  0x4747fff9         argv[1]
0x4747ffd0  0x4747ffed         argv[0]
0x4747ffc8  0                  가짜 반환 주소

argv = 0x4747ffd0 (rsi) · argc = 2 (rdi) · rsp = 0x4747ffc8

따라가는 길: argv 0x4747ffd0 → 한 칸 위 [0x4747ffd8] = 0x4747fff9 → 그 주소의 "onearg\0". args.c의 루프는 argv[2] 칸 [0x4747ffe0] = 0에서 멈춤. 모든 포인터가 유저 스택 페이지 안을 가리킴 → 유저 모드에서 그대로 역참조 가능

커널 버퍼 주소를 넣으면: KERN_BASE 위 주소라 PTE에 유저 비트가 없음 → 유저 모드 읽기 = 페이지 폴트 → args가 argv[1] 줄에서 죽음. 그 버퍼(process_exec의 file_name 페이지)는 load 직후 해제되기도 함 → 문자열 자체를 스택으로 복사해야 하는 이유

문자열 합 7 + 12 = 19 = 문서 예시 4 + 4 + 3 + 8 → 문자열 끝 ffed까지 문서 표와 동일. 그 아래는 인자 수가 달라 2칸 짧음

Point %rsi to argv (the address of argv[0]) and set %rdi to argc.

변형args-dbl-space (two spaces!)이면 argc와 rsp는? 패딩은 몇 바이트?
